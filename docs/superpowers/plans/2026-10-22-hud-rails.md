# Side-Rail HUD in Game Space — Implementation Plan (roadmap 2.2)

**Spec:** roadmap task 2.2 in `docs/superpowers/plans/2026-10-21-visual-overhaul-roadmap.md`:
"Move the HTML `#hud` into a canvas HUD (scales with FIT, ≥ 44 px targets after scaling to a 360
px-high phone viewport); keep DOM overlays (codex, settings, story) but restyle them with
touch-sized CSS. *Accept:* HUD usable at 844×390 and 932×430 landscape captures."

**User decisions (2026-10-22):** (1) **side rails** — the map keeps its 1280×720 world in the
middle of a wider canvas, HUD in a rail on each side; (2) **DOM in game space** instead of a
literal canvas HUD — the HUD stays HTML but lives in a layer pinned over the canvas and scaled by
the same FIT factor (one CSS transform), so it "scales with FIT" while 2.1's DOM long-press /
confirm / tooltips, 2.3's audit and the HUD tests keep working.

## Geometry (controller ruling)
44 CSS px on a 360-px-high viewport = 88 game px (scale 0.5). One column per rail fits only ~7
such buttons; we have 15 controls + stats + hero card. So each rail is a **2-column grid**:
`RAIL_WIDTH = 176` (2 × 88) → canvas **1632 × 720**. Checks: 844×390 → scale 0.517, map 662×372,
cell 88 game px = 45.5 CSS px ✓; 932×430 → scale 0.571 → 50 CSS px ✓; Pixel 7 863×360 → 0.5 →
44 ✓; iPhone 14 emulation 750×340 → 0.46 → 40.4 CSS px (floor 40 there); desktop 1280×720 →
0.784, map 1004×565 (today 1036×583, −3%). Tunables in a new `src/data/layout.js`:
`WORLD_WIDTH = 1280`, `WORLD_HEIGHT = 720`, `RAIL_WIDTH = 176`,
`CANVAS_WIDTH = WORLD_WIDTH + 2 * RAIL_WIDTH`, `HUD_CELL = 88`, `MIN_TOUCH_PX = 44`,
`MIN_TOUCH_PX_SMALL_PHONE = 40`.

## Rail layout (game px; 2 columns of 88, rows of 88)
- **Left rail:** stats block (lives / gold / wave / kills, 2 rows, full width) · hero card
  (portrait + level + HP/XP bars, 1 row, full width) · Q W / E ✕Cancel (2 rows) · Pause · 2×
  (1 row) · Codex · Exit (1 row) → 7 rows (616 px) + gaps.
- **Right rail:** 6 tower buttons (3 rows × 2) · Send Wave (1 row, full width; wave-preview
  popover opens to the LEFT, over the map) → 4 rows, vertically centred.
- Fonts in game px sized so the smallest text is ≥ 11 CSS px at scale 0.46 (≥ 24 game px).

## Global Constraints (bind every task)
1. **No gameplay change.** World coordinates, map data, radii, costs, priority order unchanged.
   The map/world stays 1280×720: every world-size read uses `WORLD_WIDTH/HEIGHT`, never
   `this.scale.width/height` (which becomes the canvas size).
2. **Tunables in `src/data/layout.js`**; no literal 1280/1632/176/88 in logic (map data and the
   headless sim excepted).
3. **Pure logic Vitest-tested** (jsdom, Phaser mocked): world↔page maths, HUD-layer transform,
   rail audit verdicts. **Mutation-check** each new test.
4. **DOM ownership unchanged:** GameScene owns `#hud`/`#bottom-bar` contents' listeners
   (ids/classes keep their names — reparenting static DOM is fine; the shutdown clone lists must
   still find every node), UIScene owns `ability-*`. Floating elements positioned from
   `getBoundingClientRect` (`#tower-tooltip`, `#ability-card`, `#enemy-inspector`,
   `#hero-inspector`, `#inspect-peek`) stay OUTSIDE the transformed layer (a transformed ancestor
   changes `position:fixed` and rect units).
5. **Listener lifecycle:** named, bound once, removed where the owner tears down; the HUD-layer
   fitter is page-lifetime (owned by `main.js`).
6. **Desktop:** looks right at 1280×720 and wider windows; hover tooltips/one-click actions as
   today. New touch sizing only under `(pointer: coarse)`.
7. Phaser 3.90 — verify APIs in `node_modules/phaser/src` (camera `setViewport`, `pointer.worldX`,
   ScaleManager `resize` event, `displayScale`, `canvasBounds`). `this.scene.pause()` is queued.
8. Each task ends with `npm test` green (count) and `npm run build` OK; browser checks with REAL
   input (Playwright `page.mouse` / `page.touchscreen.tap`, CDP touch for holds); LOOK at the
   screenshots.

### Task 1: Wider canvas, map in a camera viewport, world↔page helpers

**Files:** create `src/data/layout.js`; modify `src/main.js`, `src/scenes/GameScene.js`,
`src/scenes/MapEditorScene.js`, `src/systems/AmbientBackgroundLayer.js`,
`src/scenes/InputController.js`, `src/scenes/InspectController.js`, `src/systems/CoinFx.js`,
`src/systems/viewport.js`, `scripts/capture.mjs`, tests.

1. `main.js`: `width: CANVAS_WIDTH, height: WORLD_HEIGHT` (FIT, CENTER_BOTH unchanged).
2. GameScene `create`: `this.cameras.main.setViewport(RAIL_WIDTH, 0, WORLD_WIDTH, WORLD_HEIGHT)`
   (map background colour then fills the map viewport only). Replace every world-size read of
   `this.scale` (PathManager size ~142, backdrop ~217, blockers ~1865, road texture ~1890) with
   `WORLD_WIDTH/HEIGHT`. Same for `AmbientBackgroundLayer` (~31) and MapEditorScene (`this.W/H` +
   the same camera viewport so editing coordinates stay world coordinates).
3. InputController: every map hit test and the tap point use `pointer.worldX/worldY`
   (~61 press origin for target/tap, ~65 `inspectableAt`, ~88 `_onTap`); the CSS slop keeps using
   a delta in ONE consistent space. Update fixtures to supply `worldX/worldY`.
4. `viewport.js`: add `worldToPageCss(scale, wx, wy)` = `gameToPageCss(scale, wx + RAIL_WIDTH, wy)`
   and `pageToWorld(scale, px, py)` = `pageToGame(...)` minus `RAIL_WIDTH` on x. Callers switch:
   `_openPanelFromTap` (~1273), InspectController peek (~306) and cards (~336) → `worldToPageCss`;
   CoinFx `_resolveTarget` (~62-72) → `pageToWorld`, and its clamp uses the CANVAS extents in world
   coordinates (x ∈ [−RAIL_WIDTH, WORLD_WIDTH + RAIL_WIDTH]) so a coin can fly into a rail. Tests
   with a non-1:1 scale and the offset (round-trip; a world point maps to the canvas rect + (x +
   176)/ds).
5. Capture harness: `clickGamePoint` (~120) converts world → canvas with the offset and divides
   by `CANVAS_WIDTH`.
6. Interim state is expected: the DOM bars still sit above/below; the rails are empty canvas.
   Verify (frozen frame, real input): desktop + iPhone — map drawn in the middle with empty
   rails; tap a pad (archer armed) → tower placed on THAT pad; tap a tower → panel opens at the
   tower; long-press an enemy → peek at the enemy; a kill → coin flies toward the gold counter.
   Commit: `feat(layout): 1632-wide canvas with the map in a camera viewport`.

### Task 2: Rail-aware layout audit (the failing check first)

**Files:** `src/systems/layoutAudit.js` + test, `scripts/capture.mjs`.

1. Capture devices: add `phone844` (viewport 844×390, DPR 3, `isMobile`, `hasTouch`, iPhone UA)
   and `phone932` (932×430, same), each with a `portrait` descriptor of the swapped size; keep
   desktop/iphone/pixel/ipad. `--devices` accepts them.

   `MIN_TOUCH_PX` (44) except devices narrower/shorter than 844×390 (iphone 750×340) =
   `MIN_TOUCH_PX_SMALL_PHONE` (40). Retire `barWrapProblems` (the bottom bar is gone) — delete it
   and its tests, and its call in the harness. Tests per problem + boundaries.

   `#open-codex`, `.tower-btn`, `#exit-btn`, `#wave-btn`, `.ability-btn-wrap`); rails are the
   rects of `#rail-left` / `#rail-right` (missing → `rails missing`); run `railProblems` on every

4. **Prove it fails:** on the Task 1 tree, `npm run capture -- --screens --maps 0 --devices

### Task 3: The HUD layer in the rails

1. Markup: inside `#game`, a `#hud-layer` (absolute, `width: CANVAS_WIDTH px; height:
   WORLD_HEIGHT px` via CSS custom properties set from `layout.js` at boot, `transform-origin: 0

   (each `RAIL_WIDTH` wide, full height, `pointer-events: auto`, dark rail background) laid out as
   CSS grids of `HUD_CELL` cells per the Rail layout section. MOVE the existing `#hud` children and
   `#bottom-bar` children into the rails, keeping every id/class (`#hud` and `#bottom-bar` may

   Body is no longer a 3-row flex column: `#game` fills the safe-area box.
2. `src/ui/hudLayer.js`: pure `hudLayerTransform({ canvasRect, gameRect, canvasWidth })` →

3. Floating elements (outside the layer): `#tower-tooltip` opens to the LEFT of a right-rail

   `@media (max-height: 500px)` block and the `#hud, #bottom-bar { flex-wrap }` portrait rule

5. CoinFx target (`#stat-gold`'s parent) and the life-lost pulse (`#stat-lives`'s parent) keep

6. Verify: `npm run capture -- --screens --maps 0 --devices desktop,phone844,phone932,iphone,pixel`

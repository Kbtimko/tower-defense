# Tier-4 Sweep (backlog #74) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `npm run balance -- --t4` reports each tower anchored at T3, 4A and 4B on every tier-4 map. The default report and sim behaviour are unchanged.

**Architecture:**
- The sim honours an optional branch, tier cap and tag carried on build purchases.
- The pure `src/sim/t4Sweep.js` wraps the best-strategy plan with an anchor and runs the sweep.
- `scripts/balance.mjs` prints the section only when the flag is set.

**Tech Stack:** Vanilla JS ES modules, Vitest, Node script.

**Spec:** `docs/superpowers/specs/2026-11-19-t4-sweep-design.md`

## Global Constraints
- With no `branch`, `maxTier` or `tag` on any purchase, sim output is exactly today's. `src/sim/__fixtures__/legacyGolden.json` stays untouched and `waveTiming.test.js` stays green.
- The default `npm run balance` output is byte-identical (the controller diffs it).
- Field names:
  - A build purchase is `{ type, slotIndex, branch?, maxTier?, tag? }`.
  - A sim tower carries `branchPref` (default `null`), `tierCap` (default `null`) and `tag` (default `null`).
  - An upgrade purchase is `{ upgrade: true, towerIndex, branch? }`.
- The tier-4 key is `tier4${p.branch ?? t.branchPref ?? 'A'}`. `t.branch` is set to that letter.
- Sweep maps: `MAPS.filter(m => (m.maxTierAllowed ?? 4) === 4)`. Sweep towers: `Object.keys(TOWER_DEFS)`. Anchor tiers: `T3`, `4A`, `4B`.

## Review Focus
- Greedy must not take a `tierCap: 3` anchor to tier 4, and must score the anchor's tier-4 upgrade with its `branchPref`.
- An anchor that is not yet affordable holds the gold (returns `[]`) and does not hand it to the base plan.
- The anchor slot must be excluded from the base plan's free slots in the same build phase.
- A purchase for a tier above the map's `maxTierAllowed` stays refused, as today.

### Task 2: `src/sim/t4Sweep.js`

**Files:** Create `src/sim/t4Sweep.js`. Test `src/sim/t4Sweep.test.js`.

**Interfaces:**
- Consumes Task 1's purchase fields, `bestStrategy`/`strategyPlan` (`src/sim/strategy.js`), `findWinMultiplier` (`src/sim/deficit.js`), `simulateMap`, `rankSlots` (`src/sim/buildPolicy.js`, coverage-ranked slots), `TOWER_DEFS` and `MAPS`.
- Produces:
  - `ANCHOR_TIERS = ['T3', '4A', '4B']`
  - `anchoredPlan(basePlan, { type, tier })`, which returns a `buildPlan(ctx)` function
  - `runT4Sweep(map, waves, { waveTiming } = {})`, which returns `{ map, baseline: { label, multiplier, livesKept }, rows: [{ type, tier, multiplier, livesKept }] }`
  - `sweepMaps()`, which returns the tier-4 maps

- [ ] **Step 1: Failing tests.** All of these can use a stub `basePlan` that records its `ctx`.
  - The first call buys the anchor at the top-ranked free slot with `tag:'anchor'`, `maxTier` 3 for `T3` and 4 otherwise, and `branch` `'A'` or `'B'` for 4A/4B (none for T3).
  - When the anchor is unaffordable it returns `[]` and does not call basePlan.
  - Once the anchor exists it upgrades it one tier per affordable step up to its tier (the upgrade carries the branch at tier 4), then calls basePlan with `gold` reduced by what it spent and `slotsUsed` including the anchor slot.
  - It never upgrades past the anchor's tier or the map's `maxTierAllowed`.
  - `runT4Sweep` on a real tier-4 map returns `Object.keys(TOWER_DEFS).length * 3` rows, each with a numeric or null `multiplier` and `livesKept` in [0, 1].
  - `sweepMaps()` equals `MAPS.filter(m => (m.maxTierAllowed ?? 4) === 4)`.
  - Keep the slow test to one map.
- [ ] **Step 2:** run the file and confirm it FAILS (module missing).
- [ ] **Step 3: Implement.**
  - `anchoredPlan` finds the anchor by `ctx.towers.findIndex(t => t.tag === 'anchor')`.
  - The slot is the first of `rankSlots(ctx.buildZones, ctx.path)` not in `ctx.slotsUsed`.
  - Upgrade costs come from `TOWER_DEFS[type][tierKey]`.
  - `runT4Sweep` uses `bestStrategy(map, waves, { waveTiming })` for the base strategy and baseline. Each row's `livesKept` comes from one `simulateMap` run, and its `multiplier` from `findWinMultiplier` with the anchored plan.
- [ ] **Step 4:** the file passes and `npm test` is green.
- [ ] **Step 5: Commit** `feat(sim): tier-4 sweep — anchor one tower at T3, 4A or 4B over the best strategy`.

# Tower Art (roadmap 4.2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prompts and jobs for 6 new tower bases and 12 tier-4 branch looks, then two generate → review → apply rounds.

**Architecture:** `buildPrompt` learns a `{subject}` slot so the art-bible anchor can be used verbatim; PROMPTS.md carries the exact prompts; two job files drive pipeline v2. Stages 1–2 are local runs by the controller with the user's picks.

**Tech Stack:** Vanilla JS ES modules, Vitest, pipeline v2 (`npm run art -- --job`, `art:review`, `art:apply`).

**Spec:** `docs/superpowers/specs/2026-11-16-tower-art-design.md`

## Global Constraints
- The sprite style anchor is the art bible §7 text verbatim, with `{subject}`.
- `buildPrompt` without a `{subject}` slot behaves exactly as today (`style. subject`).
- Prompt subjects are copied verbatim from the spec §2. Bullet labels use the accent hex: archer `#ffb000`, mage `#dd00ff`, cannon `#ff7a2f`, ice `#00eeff`, sniper `#ff3355`, barracks `#ffd34d`.
- Jobs: `towers-base` (8 candidates, 6 bases), `towers-branches` (8 candidates, 12 variants, `"init": "base"`, `"strength": 0.65`). Task 3 replaces `towers-branches` with `towers-tiers` (6 candidates, 24 variants, strength t2 0.6 / t3 0.7 / t4 0.75).
- Never contact Draw Things (port 7860) in Tasks 1–2; never run `npm run art` without `--dry-run`/`--fake`; never run a non-dry `art:apply`.

## Review Focus
- An anchor whose `{subject}` appears twice, or a subject containing `{subject}`, must not loop or double-substitute.
- The legacy generator (`npm run art -- --kind sprite --dry-run`) must print prompts with the subject inside the anchor sentence, not after it.
- Every tower has exactly one base, one `t4a` and one `t4b` bullet; a typo'd key (e.g. `t4c`) is caught by the job resolving with zero errors.

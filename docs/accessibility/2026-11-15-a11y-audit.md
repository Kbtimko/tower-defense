## Accessibility Audit: Last Light (map select, story dialog, in-game HUD, tower panel, codex)
**Standard:** WCAG 2.1 AA (plus 2.2's 2.5.8 target size) | **Date:** 2026-11-15
**Build:** `main` @ `22c103f`, local dev server, 1280×800 viewport, Chromium
**Method:** axe-core 4.10.2 automated scan on 6 screens + scripted keyboard walk (Tab / Escape) + visual review of screenshots.
**Limits:** axe only sees the DOM. Everything Phaser draws on the canvas (map, slots, enemies, in-world numbers, hero) is invisible to it and was reviewed by eye only. No screen-reader pass (VoiceOver/NVDA) was done.

### Summary
**Issues found:** 10 | **Critical:** 0 | **Major:** 4 | **Minor:** 6

The DOM HUD is in decent shape: every control is a real `<button>`, Tab reaches all of them, Escape closes the story dialog and the codex, and HUD/panel body text passes contrast. The real gaps are the dimmed "can't afford" tower buttons, dialogs that don't move focus, and the fact that building towers needs a mouse.

### Findings

#### Perceivable
| # | Issue | WCAG | Severity | Recommendation |
|---|-------|------|----------|----------------|
| 1 | Unaffordable tower buttons dim their cost and name to **2.88:1** (`#6f5f12` cost) and **2.17:1** (`#4d4d56` name) on `#131329`, at 10–11px. Players read these costs to plan the next buy, so this is information, not decoration. axe: 10 nodes, "serious". | 1.4.3 | 🟡 Major | Keep the "can't afford" signal but stop fading the text: dim the icon/border only, or show the cost in a muted red at ≥4.5:1, or add a 🔒/"need 30g" label. |
| 2 | Tower-panel "Effective vs" (green) / "Weak vs" (pink-red) and the armour ⚠ line use red/green as the main cue. Text labels do carry the meaning, so it isn't color-only, but the 11px serif on dark navy is hard to read. | 1.4.1 / 1.4.3 (advisory) | 🟢 Minor | Bump panel text to 12–13px, use a sans font for numbers, and add ✔/✖ glyphs next to the colored lines. |
| 3 | Locked hero abilities W/E are nearly invisible (very low contrast glyphs). Fine for a disabled state, but players can't tell what unlocks later. | 1.4.11 (advisory, disabled exempt) | 🟢 Minor | Raise to ~3:1 and add a tooltip "Unlocks at hero level N". |

#### Operable
| # | Issue | WCAG | Severity | Recommendation |
|---|-------|------|----------|----------------|
| 4 | **Building, selecting and upgrading towers, and moving the hero, need a mouse/touch** — slots and towers exist only on the canvas. Tower buttons can be focused, but there's no keyboard way to pick a slot. | 2.1.1 | 🟡 Major | Add keyboard slot cycling: with a tower type armed, arrow keys / Tab move a highlight between free slots, Enter builds; on a built tower, Enter opens the panel. Also helps controllers and the iOS port (backlog #9). |
| 5 | **Dialogs don't take focus.** When the story dialog opens, focus stays on `<body>`; when the codex opens, focus stays on the Codex button behind it. Keyboard users have to Tab through the page to reach Skip/Next/Close. (Escape does close both. ✅) | 2.4.3 | 🟡 Major | On open, focus the primary button (Next ▸ / Close); trap Tab inside while open; return focus to the opener on close. |
| 6 | **The story banner's ✕ button is focusable while off-screen** (banner is parked at `top:-130px`, still `display:flex`). It's an invisible tab stop on the map-select screen. | 2.4.7 / 2.4.3 | 🟢 Minor | Hide the banner with `visibility:hidden` or `inert` when it's not showing. |
| 7 | Focus ring is the browser default 1px outline, which is faint on the dark navy UI. | 2.4.7 | 🟢 Minor | Add a shared `:focus-visible` style (e.g. 2px gold `#ffd700` outline + offset) to match the HUD's accent. |
| 8 | Small targets: the in-game **Codex button is 63×19px** (below the 24px minimum in WCAG 2.2 2.5.8); 2x speed is 51×24. Relevant for the planned touch/iOS work. | 2.5.8 (2.2 AA) | 🟢 Minor | Make all HUD buttons ≥ 32px tall (44px for touch). |

#### Understandable
| # | Issue | WCAG | Severity | Recommendation |
|---|-------|------|----------|----------------|
| 9 | **Inconsistent buttons.** On map select, Story and Codex render as unstyled browser buttons while Upgrades/Heroes/Audio are themed; the in-game Codex button is also unstyled next to the themed Pause. Looks unfinished and breaks the visual pattern players learn. | 3.2.4 (consistent identification, advisory) | 🟢 Minor | Give `#open-story-log`, `#open-codex-ms` and `#open-codex` the same class as their neighbours. (Probably the single highest polish-per-minute fix in this list.) |

#### Robust
| # | Issue | WCAG | Severity | Recommendation |
|---|-------|------|----------|----------------|
| 10 | No `<main>` landmark or `<h1>`; HUD stats are bare `div`s, so a screen reader hears "25 Lives 130 Gold…" as loose text with no live updates. Tooltip wrappers (`ability-*-wrap`, `wave-btn-wrap`) add duplicate tab stops — deliberate, so tooltips work on disabled buttons (see `WavePreviewPopover.js`), but each control is announced twice. | 1.3.1 / 4.1.2 | 🟡 Major (for SR users) | Wrap the HUD in `<header>`/`<main>`, make "LAST LIGHT" an `<h1>`, add `aria-live="polite"` to lives/gold/wave. For the wrappers, use `aria-disabled` on the button instead of `disabled`, so the wrapper `tabindex` can go. |

### Priority Fixes
1. **Readable costs on unaffordable towers (#1)** — every player, every wave; tiny CSS change.
2. **Consistent button styling (#9)** — tiny CSS change, biggest "looks professional" win.
3. **Dialog focus management (#5)** — keyboard users and anyone who hits Enter expecting "Next".
4. **Keyboard/controller slot selection (#4)** — larger feature; pairs with touch/iOS work, so spec it alongside backlog #9 / #26.
5. Minor polish: focus ring, off-screen ✕, target sizes, landmarks/live regions.
